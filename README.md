# Анализ структуры видео-сторителлинга — локальный запуск

## Установка
```bash
pip install openai
```

## Файлы
- `taxonomy.py` — таксономия тегов (можно редактировать список, ничего больше менять не нужно)
- `segmenter.py` — основной скрипт: режет текст на блоки и тегирует через OpenAI (gpt-4o-mini)
- `validator.py` — проверяет, что блоки реально совпадают с исходным текстом (без выдумывания)
- `story1.txt` — тестовый отрывок (история №1 про КАЗ-608 «Колхида»)
- `full_text.txt` — весь файл с 7 историями (для будущих прогонов)

## Запуск теста на одной истории

```bash
export OPENAI_API_KEY=sk-...твой_ключ...
python3 segmenter.py story1.txt out_story1.json
python3 validator.py story1.txt out_story1.json
```

`segmenter.py` создаст `out_story1.json` со списком блоков:
```json
{
  "blocks": [
    {"text": "...", "tag": "ARC_OPEN", "tension_score": 3, "loop_id": null, "reasoning": "..."}
  ]
}
```

`validator.py` выведет в консоль:
- покрытие текста (% от исходника, который реально нашёлся в блоках по порядку)
- список проблем (если блок не нашёлся дословно в тексте, или модель пропустила кусок)
- частоту тегов

## Что смотреть в результате
1. Открой `out_story1.json` — пробегись глазами, совпадает ли разметка с твоим интуитивным
   пониманием структуры (где хук, где петли, где переломы).
2. Посмотри на вывод `validator.py` — если покрытие <95% или много issues, значит модель
   перефразирует вместо дословного цитирования, и промпт в `segmenter.py` надо ужесточить
   (можно прислать мне лог — поправим).
3. Проверь `loop_id` — совпадают ли пары OPEN_LOOP/CLOSE_LOOP по смыслу.
