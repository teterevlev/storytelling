# Правила кластеризации тегов по психологическому механизму

Документ задаёт процедуру офлайн-кластеризации story-beat’ов внутри одного функционального тега (OPEN_LOOP, TENSION, CONTEXT, …).  
Исходные принципы — из `open_loop.md`; здесь зафиксирован **пайплайн**, который не даёт модели игнорировать запрет на группировку по теме на больших выборках (сотни сырых абзацев).

> **Статус для приложения:** рабочий каталог — `clusters_canon.md` после одного прагматичного прогона v2. Решение зафиксировано в `PRAGMATIC_FREEZE.md`. Не запускать цикл перекластеризаций без нового критерия приёмки.

Связанные файлы:
- `open_loop.md` — исходная инструкция и эталонный результат для OPEN_LOOP
- `clusters_review_1-5.2.md` — предыдущий черновик (не эталон процедуры)
- `clusters_examples_index_1-5.2.md` — нумерация примеров по тегам и источникам

---

## 1. Цель

Найти **естественные кластеры** внутри одного тега, объединяя примеры **только по психологическому механизму** воздействия на зрителя.

Психологический механизм — не текст, не сюжет и не стиль формулировки, а общий принцип воздействия. Если два примера используют один принцип, они в одном кластере, даже если содержание полностью разное.

Результат discovery — каталог механизмов (формула + позже название).  
Полная разметка всех блоков тега **не обязательна** на этапе построения каталога.

---

## 2. Жёсткий запрет (всегда)

Полностью игнорируй и **не используй как основание для группировки**:

- тему, сюжет, исторический период;
- персонажей, объекты, страны, бренды, имена собственные;
- числа, единицы измерения, «узнаваемые» факты;
- повторяющиеся слова, синтаксис, вводные обороты.

Не группируй примеры по содержанию.

Проверка «на пальцах»: если после замены всех сущностей на X/Y/Z примеры перестают казаться «одной кучей», значит группировка была тематической — кластер невалиден.

Запрещены названия и формулы, для которых нужны доменные слова («гравитация», «завод», «планета», «война» и т.п.) как единственный смысл кластера.

---

## 3. Почему нельзя кластеризовать сотни сырых абзацев сразу

На большом батче сырого текста модель делает два дела сразу: понять механизм и сгруппировать соседей. Второй сигнал (лексика/домен) сильнее инструкции «игнорируй тему».

Батчи сырых текстов **недостаточны**:

- внутри батча тема всё равно доминирует;
- между батчами один механизм размножается в разные кластеры;
- merge батчей снова тянет к сюжету.

Сырые батчи допустимы только там, где это явно указано ниже (и только на абстракциях или на проверке).

---

## 4. Пайплайн (обязательный порядок)

```text
сырой block.text
    → A. абстракция механизма (по одному примеру)
    → B. выборка для discovery
    → C. кластеризация абстракций выборки
    → D. ревизия (split / merge / residual)
    → E. формула, затем название (отдельные итерации)
    → F. мягкая проверка на отложенной части (не полная разметка)
```

Полное назначение всех оставшихся примеров в каталог **не проводится** на этом этапе.

---

### A. Абстракция механизма (проход 1)

**Вход:** один сырой пример (допустимо 1–3 за вызов, не десятки).  
**Выход:** только механизм, без сущностей.

Формат ответа на пример:

```text
n: <номер примера>
механизм: <одно предложение без имён/объектов/стран/чисел>
шаги:
  X → …
  → …
запрещённый_остаток: <если без конкретных деталей механизма не видно — кратко почему>
```

Правила прохода A:

- нельзя переносить в абстракцию имена, объекты, страны, эпохи, числа;
- нельзя писать «про космос / про завод / про войну»;
- если механизм не угадывается без темы — пометить пример как кандидат в residual, не выдумывать механизм.

Абстракции можно делать параллельно: соседи в одном вызове не нужны и вредны.

Сохранять пару: `n` ↔ `abstract` (сырой текст для discovery больше не подавать).

---

### B. Выборка для discovery

Из всех абстракций тега взять **выборку для построения каталога**, не весь корпус.

Рекомендации:

- ориентир: **60–100** абстракций на тег (меньше — если примеров мало);
- стратификация по источникам (1.json, 2.json, …), чтобы не застрять в одном домене;
- остальное — **holdout** для мягкой проверки (п. F), не для изобретения новых кластеров.

Shuffle порядка перед кластеризацией, чтобы не закреплять порядок источников.

---

### C. Кластеризация абстракций выборки (проход 2)

**Вход:** только абстракции выборки (короткие entity-free строки).  
**Не подавать** сырые абзацы.

Задача — как в `open_loop.md`:

- естественные кластеры по механизму;
- не стремиться к заранее заданному числу;
- лучше разделить похожие механизмы, чем смешать разные;
- синглтон допустим **только** если механизм явно уникален и не сводится к остатку;
- пример без явного сходства с другими → отдельный кластер или «временно неклассифицированные»;
- на этом этапе **не именовать** кластеры и не тащить термины из риторики/психологии/сценарного мастерства.

Для каждого кластера вывести:

1. Номер кластера.
2. Предложение: **«Все эти примеры работают одинаково, потому что…»** (только механизм).
3. Черновую последовательность шагов без сюжета.
4. Список номеров `n` из выборки.
5. Если пример тянет к нескольким кластерам — основной и дополнительные.
6. **«Почему эти примеры нельзя разделить как минимум на два разных кластера?»**

Запрещено:

- оценивать качество примеров;
- предлагать улучшения сценариев;
- придумывать новые примеры;
- объяснять, как использовать кластеры.

Батчить на этом шаге можно **только абстракции**. Если абстракций в выборке всё ещё много — дробить discovery на подвыборки, затем склеивать **по совпадению формул механизмов**, не по сюжетам сырых текстов.

---

### D. Ревизия каталога (аналог open_loop.md:38–39)

После первого прогона по выборке:

1. **Неоднородные кластеры** — разрезать заново по тем же правилам (новые кластеры из частей).
2. **Псевдокластеры** (слабая общая тема, нет устойчивого механизма, «просто остатки») — объединить и снова попытаться кластеризовать; что не сложится — в **«Временно неклассифицированные»**.
3. Оставшийся residual после этого — нормально.

Дополнительно (анти-раздувание):

- кластер из 1–2 примеров без чёткой формулы, отличной от уже существующих → в residual, не в каталог;
- если единственное отличие кластеров — объект/домен при одной формуле → объединить;
- если название/описание невозможно без доменного слова → переписать или отправить в residual.

Полная обязательная «вторая кластеризация всего корпуса» не требуется — ревизия идёт по каталогу, построенному на выборке.

---

### E. Формула и название (отдельные итерации)

Только после стабилизации состава кластеров на выборке.

1. Для каждого кластера — **короткая формула** шагами X/Y без сюжета.  
2. Отдельным шагом — **короткое название** по механизму, без доменных слов.

Аудит: формула и название должны оставаться осмысленными, если все примеры кластера мысленно перефразированы и обезличены.

---

### F. Мягкая проверка на holdout (не полная разметка)

Полное назначение всех оставшихся примеров **не проводить**.

Взять **часть** holdout (например 20–40 абстракций, снова со стратификацией по источникам) и для каждой:

- либо указать наиболее близкий кластер из **готового whitelist** (номер / формула);
- либо сказать «ни один не подходит» / residual;
- **запрещено** предлагать новые кластеры на этом шаге.

Как читать результат (нестрого):

- большинство holdout уверенно ложится в 1–2 кластера каталога → каталог жизнеспособен;
- частый «ни один» при похожих механизмах → дыра в каталоге: вернуться к C/D на расширенной выборке или разрезать/добавить механизм осознанно;
- holdout липнет к одному кластеру по Domену (все «космические» в один) при разных абстракциях → тематическая утечка, чинить формулы/границы;
- единичные промахи — норма, не повод плодить синглтоны.

Итог проверки — заметки к правке каталога, а не полный файл назначений.

---

## 5. Чего не делать

| Действие | Почему нельзя |
|----------|----------------|
| Кластеризовать 400+ сырых абзацев одним/несколькими сырыми батчами | Тема побеждает инструкцию |
| Discovery на всём корпусе сразу | Раздувание и тематические корзины |
| Полная разметка всех блоков как часть построения каталога | Смешивает assignment и discovery; дороже; провоцирует новые номера |
| Merge кластеров по сюжетам сырых текстов | Возвращает утечку темы |
| Именовать кластеры до стабилизации состава | Имена закрепляют ложную группировку |
| Считать синглтон нормой «по умолчанию» | Раздувает каталог остатками |

---

## 6. Критерии валидного кластера

Кластер валиден, если одновременно:

1. Все члены объединены одним механизмом воздействия на зрителя.
2. Формула не ссылается на конкретный домен/объект.
3. После обезличивания примеров состав кластера остаётся убедительным.
4. Кластер нельзя безболезненно разбить на два разных механизма (ответ на контрольный вопрос из п. C).
5. Это не «остаток, которому дали имя».

Иначе — split, merge или residual.

---

## 7. Выходные артефакты на тег

1. `abstracts` — `n`, механизм, шаги (для всех или хотя бы для выборки + holdout-проверки).  
2. `clusters_draft` — кластеры по выборке до имён.  
3. `clusters_canon` — после ревизии: номер, формула, название, список `n` из выборки, residual.  
4. `holdout_notes` — краткий отчёт мягкой проверки (без полного assignment).

Нумерация `n` — внутри тега, как в `clusters_examples_index_1-5.2.md` (или актуальный индекс источников).

---

## 8. Порядок работ по всем тегам

1. Зафиксировать источники и индекс `n`.  
2. Для каждого тега независимо: A → B → C → D → E → F.  
3. Не переносить кластеры между тегами.  
4. Старый `clusters_review_*.md` не считать источником истины, если он собран сырыми батчами; при пересборке каталог заменяется.

---

## 9. Связь с приложением

- В БД (`tag_subclusters`) попадает только **канонический каталог** после E (и правок по F).  
- Классификатор новых текстов назначает только в whitelist активных кластеров и **не создаёт** новые.  
- Residual в классификацию как целевой класс не входит (если отдельно не решено иначе).
